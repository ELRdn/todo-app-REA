# 06. 合成 — 5つのUIから「Spine」を作る

5アプリの観察を、1つのTodoアプリのデザインシステムに落とす。
名前は **Spine（背骨）**。1日の時間軸を背骨にし、タスクはそこに付く椎骨として扱う。

---

## 1. 設計原則（8つ）

| # | 原則 | 根拠になった観察 |
|---|---|---|
| 1 | **時間が主軸。リストはレンズ。** | Toggl / Structured / Tiimo はすべて時間軸がホーム。Asanaだけがリスト。 |
| 2 | **1行 = 1アクション。** 時間・場所・エネルギー・文脈を1行に収める。 | 5アプリの行の構成がすべて違う＝「何を入れるか」が設計の核。 |
| 3 | **空き時間はオブジェクト。** 空白を提案に変える。 | Structured `30min of free time?` / Toggl `0h free`。 |
| 4 | **完了は「閉じる」、ご褒美は「控えめ」。** | Tiimoのリング、Asanaの緑塗り。Habiticaの過剰な報酬は業務では不要。 |
| 5 | **色 = 文脈。装飾ではない。** | Togglのプロジェクト色、Structuredのカテゴリ色。 |
| 6 | **数字は隠さない。ただし主役は1画面に1つ。** | TogglのKPI、Asanaの進捗。数字を並べすぎると読めない。 |
| 7 | **書体がブランド。色に頼らない。** | TiimoのRecoleta、StructuredのInter 300、AsanaのLausanne 300。 |
| 8 | **動きは確認。娯楽ではない。** | Habiticaのパーティクルは世界観の一部。汎用Todoでは不要。 |

---

## 2. レイアウト

### 2.1 デスクトップ（≥ 1024px）

```
┌────┬──────────────────┬────────────────────────────────────────────┐
│    │  Spine           │  10月25日（土）        [Day] [Week] [List]  🔍 ⌘K │ 56px
│ 64 ├──────────────────┼────────────────────────────────────────────┤
│ ▣  │  Inbox        12 │  09:00 ─────────────────────────────────  │
│ ◷  │  Today         8 │         ┌────────────────────────────┐     │
│ ▤  │  Upcoming       │         │ 09:30  深い作業 90m        ● │     │
│ ◈  │  ─────────────   │         └────────────────────────────┘     │
│    │  Areas           │  10:00 ─────────────────────────────────  │
│    │   ● Work         │         ┌────────────────────────────┐     │
│    │   ● Health       │         │ 10:00  空き 45m  散歩？     │     │
│    │   ● Home         │         └────────────────────────────┘     │
│    │  ─────────────   │  11:00 ─────────────────────────────────  │
│    │  Habits          │  ...                                       │
│    │  Review          │                                            │
└────┴──────────────────┴────────────────────────────────────────────┘
  64px      300px                     flexible
```

- **Rail 64px**: アイコンのみ（Inbox / Today / Upcoming / Areas / Habits / Review）。Asanaの左レール。
- **Sidebar 300px**: プロジェクトとエリア。Togglの「色 = プロジェクト」を継承。
- **Main**: Day view。左に時刻ガター（72px）、右にブロック。
- **Detail drawer 380px**: 右からスライド。タスク選択時のみ。
- **ヘッダー 56px**: 日付、ビュー切替、検索、コマンドパレット。

### 2.2 モバイル（< 768px）

- 下部タブ: `Today / Inbox / Habits / Search`
- FAB（+）: クイック追加
- Day view は **縦1本のタイムライン**。Structuredのday spineをそのまま採用。
- スワイプ: 左で完了、右で延期。`[INF]` 一般的なTodoアプリの慣習。

## 4. コンポーネント仕様

### 4.1 Checkbox（完了リング）

```
    ╭───╮        未完了: 1.5px solid var(--ink-3)、透明
    │   │        ホバー: 背景 var(--surface-2)
    ╰───╯        完了:   塗り var(--success)、白チェック、scale(.92)
     24px        遷移:   120ms var(--ease)
```

- **円形**。四角にしない（Tiimo / Asana / Structuredが円）。
- `aria-checked` を持つ `role="checkbox"`。
- 完了時にタイトルへ `opacity .55` + `line-through`。**赤は使わない**。

### 4.2 TaskRow

```
┌──────────────────────────────────────────────────────────────┐
│ ◯  深い作業                         ● Work   45m   ▁▁▁      │
│    09:30–11:00 · 集中度 高                         ⌘          │
└──────────────────────────────────────────────────────────────┘
 24   16px/500                         chip    mono   energy
```

- 高さ: 56px（1行）、72px（2行）。
- 左: チェック 24px + 8px。
- タイトル: 16/24、500。完了で 400。
- 右: コンテキストチップ（色ドット + 名前）、時間（mono）、エネルギー（3本バー）。
- ホバー: `--surface-2`、右端に `⋯` メニュー。
- 行全体がクリック可能（チェックだけではない）。`[INF]` Asanaの行選択の慣習。

### 4.3 TaskBlock（タイムライン）

```
┌───────────────────────────────┐
│ 09:30  深い作業          45m  │  高さ = 時間 × 1.2px/分
│ ● Work                        │  角丸 16px
└───────────────────────────────┘  背景 = カテゴリ色 12% + 左ボーダー 3px
```

- 高さは時間に比例。最小 44px。
- 左に 3px のカテゴリ色、背景はその 10–14% 透明度。
- 完了で `opacity .6`、取り消し線なし（ブロックでは線が読みづらい）。
- ドラッグで移動、下端ドラッグでリサイズ。
- 重なりは横に分割（最大3列）。`[INF]` カレンダーUIの標準。

### 4.4 FreeSlotCard

```
┌─────────────────────────────────────┐
│  ⓘ  45分 空いています               │
│      散歩する / メールを返す / 何もしない │
└─────────────────────────────────────┘
```

- 破線ボーダー、背景透明、`--ink-2`。
- 3つの提案は**その場でブロック化**できる。
- 「何もしない」を必ず入れる。`[INF]` 休憩を肯定するTiimoの思想。

### 4.5 QuickAdd

```
┌──────────────────────────────────────────────────────────────┐
│ ＋  明日 15:00 30m 歯医者 #health !high                       │
└──────────────────────────────────────────────────────────────┘
```

- 自然言語をその場でパース: 日付、時刻、所要時間、`#context`、`!priority`。
- Enterで保存、Shift+Enterで詳細、Escで閉じる。
- 保存後もフォーカスは入力欄に残る（連続入力）。Asanaの `Add task...` の思想。

### 4.6 FocusTimer

```
┌──────────────────────────────┐
│  ◔ 29:51  深い作業      ⏸  ■ │
└──────────────────────────────┘
```

- 画面右下に固定。円形プログレス + 残り時間（mono）。
- 対象タスクのブロックと色を共有。
- 終了時に通知 + 完了提案（自動完了はしない）。

### 4.7 ProgressHeader

```
今日  8 / 12 完了   ███████░░░   連続 4日
```

- 数字は1つだけ大きく（`8 / 12`）。バーは補助。
- ストリークは**控えめ**に。HabiticaのXP/HPは出さない。

### 4.8 DetailDrawer

- 幅380px、右からスライド（`--dur-2`）。
- タイトル（24/500）、メモ、日時、コンテキスト、サブタスク、添付。
- `Esc` で閉じる。フォーカストラップ。

## 5. インタラクション

| 操作 | キー | 挙動 |
|---|---|---|
| クイック追加 | `N` | QuickAddにフォーカス |
| 検索 | `/` または `⌘K` | コマンドパレット |
| 完了 | `Space` | 楽観的更新 + Undoトースト5秒 |
| 今日 | `T` | 今日にスクロール |
| ビュー切替 | `1` `2` `3` | Day / Week / List |
| 閉じる | `Esc` | Drawer / Palette |
| 移動 | `J` `K` | 次/前のタスク |
| 延期 | `S` | 明日に移動 |
| 削除 | `⌫` | Undo付き |

**状態モデル**（楽観的更新）:

```
idle → pending(optimistic) → confirmed
                           ↘ failed → rollback + toast
```

## 6. アクセシビリティ

- 本文コントラスト **4.5:1以上**。`--ink-3` はメタ情報のみ（大きい文字 or 非必須）。
- タップターゲット **44×44px** 以上（Habiticaの32px入力は反面教師）。
- `:focus-visible` に `--ring`。マウス操作では出さない。
- タイムラインは `role="list"`、ブロックは `role="listitem"` + `aria-label="09:30 深い作業 90分"`。
- 色だけで意味を伝えない。カテゴリは色 + 名前、優先度は色 + ラベル。
- `prefers-reduced-motion` を尊重。
- スクリーンリーダー用に「空き時間」も読み上げ対象。

## 7. 各アプリから「採らない」もの

| アプリ | 採らない | 理由 |
|---|---|---|
| Asana | 5層の階層、7列テーブル | 個人には過剰。深さはオプションに |
| Asana | 常駐AIチャット | コンテンツを覆う |
| Toggl | 常時タイマー前提 | 押し忘れでデータが壊れる |
| Toggl | プロジェクト色の無制限増加 | 識別不能になる |
| Habitica | XP/HP/ゴールドの常時表示 | 業務では幼稚。進捗は「完了数」で十分 |
| Habitica | 低い入力欄（32px） | タップターゲット不足 |
| Tiimo | 絵文字依存のアイコン | OS差が出る。SVGアイコン + 任意で絵文字 |
| Tiimo | パステル本文の低コントラスト | 可読性 |
| Structured | フルスクリーン動画 | LCP悪化 |
| Structured | 18,000pxの長いページ | 情報探索に不向き |

## 8. このシステムが答える問い

> **「今日、何を、いつ、どのくらいの集中度でやるか」**

Asanaのように「誰が合意したか」でも、Togglのように「いくら稼いだか」でも、
Habiticaのように「何レベルか」でもない。**今日の時間の使い方**に答える。

そのため、最初の画面は必ず **Day view**。リストは2番目のレンズ。
