# 01. Asana — 仕事を「構造」にするUI

> 観察対象: `asana.com`（マーケティング）, `app.asana.com/-/login`（ログイン）, 公式プロダクト画像7点
> Evidence: `ev_713a2929…`, `ev_3eff1be6…`, `ev_95751853…`, `ev_93c723b9…`

---

## 1. プロダクトの位置づけ

Asanaは「タスク管理アプリ」ではなく、**組織の仕事の構造（Work Graph）を可視化するOS**として設計されている。
UIの中心はタスク単体ではなく、`Portfolio → Project → Section → Task → Subtask` という入れ子の関係。
2026年版のサイトでは、この構造に **AIエージェント（AI Teammates）が同僚として参加する** ことが最大のメッセージになっている。

`[OBS]` ヒーローコピーは "The OS for **human-agent** teams"。`agent` の部分だけコーラル→ピンクのグラデーション。
`[INF]` 「人間とAIの混在チーム」を、色の混交で視覚化している。

## 2. 画面の解剖

### 2.1 マーケティング・トップ（`evidence/asana/screenshots/00.png` 〜）

```
┌──────────────────────────────────────────────────────────────┐
│ ● asana  Products  Solutions  Learning  Pricing   🌐 Log in [Contact] [Get started] │ 72px
├──────────────────────────────────────────────────────────────┤
│   ◇ floating node          ┌─────────────────┐        ◇ node │
│   "Launch product         │  The OS for      │   "Pricing   │
│    in 4 weeks"            │  human-agent     │    Strategist"│
│                           │  teams           │               │
│                           └─────────────────┘               │
│                    [G Google] [⊞ Microsoft]                  │
│                    ─────────── or ───────────                │
│                    [ name@company.com ] [Continue]           │
│                                                              │
│   ◇ Enablement                                   ◇ Product   │
│                                                  launched!   │
└──────────────────────────────────────────────────────────────┘
```

- **ヒーローの構成**: 中央の巨大コピー + 左右に浮遊する「ワークフローのノード」。ノードは細い線で接続され、
  ユーザーが「仕事の流れ」の中にいることを空間的に表現する。
- **CTAの二層構造**: Google / Microsoft のSSOを最優先（B2Bの実態に合わせる）、メールはその下。
  `Continue` は黒のピル、`Contact sales` は白のアウトライン。**主導線が2つあるのではなく、読者層で分けている**。
- **ナビ**: 高さ約72pxの白い帯。ロゴ以外は16px、右端に言語切替（地球アイコン）。
- **セクションリズム**: 白 → `#F3F3F3` → 白 → 黒（プロダクトタブ）→ 白 → 黒（フッター）。
  黒は「プロダクトの深部」と「フッター」だけに使い、色の意味を固定している。

### 2.2 プロダクト・リスト（`evidence/asana/product/project-list.png`）

```
┌──┬───────────────────────────────────────────────────────────┐
│★ │  ▣  Summer Campaign Launch Readiness ▾ ☆        👥 👥 👥 +45 [Share] [Customize] │
│▣ │  List   Timeline   Calendar   Messages                    │
│△ ├──────────────┬──────────┬────────┬──────────┬─────────┬────┤
│◇ │ Task name    │ Assignee │ Budget │ Launch   │ Channels│ +  │
│▤ │ ▼ Launch Milestones                                       │
│  │ ✓ Finalize…  │ ◯…      │$1.2M   │ Jun 01   │ Email +5│    │
│  │ ◇ Approve…   │ Emilia  │$500k   │ Jun 08   │ Email +5│    │
└──┴──────────────┴──────────┴────────┴──────────┴─────────┴────┘
```

- **左レール（約64px）**: アイコンのみ。Starred / Work / Plan / Workflow / Company。テキストラベルはホバー時。
  これは「画面を広く使う」ための典型的なB2Bパターン。
- **プロジェクトヘッダー**: 色付きの四角アイコン + プロジェクト名 + お気に入り + メンバー + Share（青）+ Customize。
- **ビュータブ**: List / Timeline / Calendar / Messages。*同じデータを4つの時間表現で見る* という宣言。
- **テーブル**: タスク名、担当者、カスタムフィールド（Budget, Launch date, Channels, Assets needed, Requesting team）。
  カスタムフィールドは自由入力ではなく**チップ（`Email +5`）**として表示され、列幅を壊さない。
- **完了状態**: 緑の塗りつぶし円 + タイトルの打ち消し線。未完了は白抜きの円。
  `[INF]` チェックボックスではなく「状態のアイコン」として扱っている（クリックで状態が変わる）。
- **セクション**: `▼ Launch Milestones` のような折りたたみ見出し。タスクの集合に名前を与える層。
- **追加導線**: セクション末尾に `Add task...` のゴースト行。**空行が入力欄を兼ねる**。

### 2.3 タスクの会話（`evidence/asana/product/task-comments-ai.png`）

- コメント欄は「人間 + AI」の混在。`Beacon`（AI）が人間と同じアバターサイズで並ぶ。
- メンションは `@Rachel Yi` のチップ、タスク参照は `◯ Quality Review #1839` のチップ。
- タイムスタンプは `20 mins ago` の相対表記。**絶対時刻を出さない**ことで「今の会話」感を出す。
- `[OBS]` 背景は薄い水色、カードは白、影はほぼなし。会話の可読性を最優先。

### 2.4 ログイン（`evidence/asana/screenshots-login/login.png`）

- 完全にミニマル。ロゴ、`Welcome to Asana`（32px/400）、`To get started, please sign in`（20px/500）、
  SSO 2ボタン（196×48、6px角丸、1px `#E1E1E1`）、メール（400×36）、`Continue`（400×36、`#4075CF`）。
- マーケティングのTWK Lausanneではなく**システムフォント**（`-apple-system, …`）。
  `[INF]` ログインは「速く・確実に」、マーケティングは「世界観」。フォントを分けている。

## 3. デザイントークン（実測）

### 3.1 タイポグラフィ

| 役割 | 値 | 備考 |
|---|---|---|
| Display | **102px / 300 / 91.8px / -2.55px** | ヒーロー。TWK Lausanne |
| H2 | 54px / 300 / -1.08px | セクション見出し |
| H3 | 24–30px / 400 | カード見出し |
| Body | **16px / 400 / 28px** | 1268要素中944が16px |
| Small | 14px / 24px | UIラベル |
| Micro | 13px / 11px | キャプション |
| Eyebrow | 16px / 500 / +0.64px / uppercase | `AI TEAMMATES` |
| Font | `"TWK Lausanne", "Helvetica Neue", Helvetica, sans-serif` | 300/350/400/450/500/550 |

**特徴**: 本文16pxに対し表示102px。**6.4倍のコントラスト**。行間は0.9倍と極端に詰め、行を「面」として見せている。ウェイトは300〜500のみで、700を使わない。
太字ではなく「大きさ」と「余白」で階層を作る。

### 3.2 カラー

| トークン | 値 | 用途 |
|---|---|---|
| `--gray-1` … `--gray-10` | `#F6F8F9` → `#151B26` | 10段のグレースケール |
| text primary | `#0D0D0D` | ほぼ黒 |
| text secondary | `#6E6E6E` / `#646F79` | 説明文 |
| surface | `#FFFFFF` / `#F3F3F3` | 白と薄灰の交互 |
| coral | `#FF5263` / `#FF7381` / `#FF9CA5` | ブランドアクセント |
| purple | `#796EFF` | AI / セカンダリ |
| teal | `#14AAF5` | リンク・情報 |
| gold | `#FFE01B` | 注意・ハイライト |
| green | `#25E8C8` | 完了・ポジティブ |
| dark mode | `#1E1F21` / `#252628` / `#2A2B2D` | ダークテーマ |

**使い方**: 画面の95%は白・黒・グレー。色は「AIエージェント」「完了」「リンク」など**意味を持つ瞬間だけ**。
グラデーション（コーラル→ピンク）はヒーローの1語だけに限定。

### 3.3 スペーシング

`8 / 16 / 24 / 32 / 48 / 64 / 80 / 96 / 112 / 128 / 144 / 160`
**8pxベースだが、後半は1.33〜1.5倍で伸びる**（64→80→96→112）。セクション間は128〜160px。
カード内は16〜24px、カード間は16〜32px。gapの実測は `4 / 8 / 16 / 32 / 12 / 24` の順に多い。

### 3.4 角丸・影

| radius | 用途 |
|---|---|
| 4px | 小さいチップ |
| 6px | ボタン・入力（ログイン） |
| 8px | カード |
| 16px | 大きいカード |
| 20px | 画像コンテナ |
| 100px | ピル（CTA・タブ） |
| 50% | アバター |

影は4段階:
`0 3px 5px rgba(36,50,66,.20)` → `0 11px 12px rgba(36,50,66,.12)` →
`0 20px 30px rgba(36,50,66,.14)` → `0 50px 60px rgba(36,50,66,.15)`
**影の色は黒ではなく青灰色（36,50,66）**。これで白背景でも濁らない。

## 5. インタラクション（観察 + 推論）

| 操作 | 挙動 | 根拠 |
|---|---|---|
| タスク完了 | 円が緑で塗られ、タイトルに打ち消し線 | `[PROD]` 画像 |
| セクション折りたたみ | `▼` が `▶` に、行が消える | `[INF]` 一般的な実装 |
| ビュー切替 | 同じデータを List/Timeline/Calendar/Messages で再描画 | `[OBS]` タブ |
| カスタムフィールド | チップをクリックして編集、`+N` で全表示 | `[INF]` |
| ホバー | 行全体が薄いピンクのグラデーション（下端） | `[PROD]` 画像下端 |
| コメント | 相対時刻、メンション、タスク参照チップ | `[PROD]` |
| AI | コメント欄にAIが参加、メモリを保持 | `[PROD]` 画像 + コピー |

モーションは最小限。`[INF]` フェードと150–200msのトランジション中心で、バウンスやパララックスは使わない。

## 6. このUIの強み

1. **情報の入れ子が迷わない**。Portfolio→Project→Section→Task の4層が、左レール・ヘッダー・セクション・行に対応。
2. **カスタムフィールドが列を壊さない**。チップ + `+N` で、どんな業務でも同じテーブルを使える。
3. **「表示形式」をデータから分離**している。List/Timeline/Calendar は同じモデルの別レンズ。
4. **AIを特別扱いしない**。Beaconは人間と同じアバター・同じコメント欄に並ぶ。AI専用画面を作らない。
5. **色の節約**。95%モノクロ、意味のある瞬間だけ色。だから長時間使っても疲れない。

## 7. 弱点・真似しない方がいい点

- **初期状態が重い**。空のプロジェクトでも列・タブ・ツールバーが多く、個人のTodoには過剰。
- **用語が多い**。Portfolio / Project / Section / Task / Subtask / Custom field / Workflow。学習コストが高い。
- **モバイルでは情報が欠落する**（推論）。7列のテーブルは横幅を必要とする。
- **AIウィジェットが画面を覆う**（撮影時）。常駐チャットはコンテンツの邪魔になる。

## 8. 盗むべきもの（Todoアプリへの移植）

| 原則 | 移植方法 |
|---|---|
| アイコンレール + ヘッダー + タブ | 個人Todoでも「Inbox / Today / Upcoming / Projects」のレールは有効 |
| チップ化されたメタデータ | 期限・タグ・優先度を「列」ではなく「チップ」で行内に |
| 空行が入力欄 | `+ Add task` を別画面にしない。リストの末尾で直接入力 |
| 完了は「塗り」 | チェックマークより、円が塗られるアニメーションの方が状態が読みやすい |
| 影の色は青灰 | 純黒の影を避ける。`rgba(36,50,66,.15)` |
| 表示形式の分離 | データモデルとビュー（リスト/タイムライン/カレンダー）を独立させる |
