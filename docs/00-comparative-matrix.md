## 5. 「タスク1行」の比較

同じ「タスク」でも、行に含まれる情報がまったく違う。

| アプリ | 行の左 | 中央 | 右 | 行の高さ |
|---|---|---|---|---|
| **Asana** | 状態円 + タイトル | 担当者 + カスタムフィールド | `+` | 約52px |
| **Toggl** | 色ドット + プロジェクト | 時間・金額 | メニュー | 約44px |
| **Habitica** | **難易度の色帯** + タイトル | メタ情報 | **`+` / `-` ステッパー** | 約56px |
| **Tiimo** | **絵文字の円** + タイトル | 時間・進捗 | 完了リング | 約64px |
| **Structured** | 時刻 | **色付きカプセル** + アイコン + タイトル | 完了円 | 約56px |

**示唆**: Todoアプリの「行」を設計するとき、最初に決めるべきは色でも書体でもなく
**「1行に何を入れるか」**。5アプリはすべて違う答えを出している。

## 6. 5つのUIパラダイム

```
Asana        ── 構造のUI       : 入れ子 + テーブル + 複数ビュー
Toggl        ── 計測のUI       : タイマー + 集計 + 予測
Habitica     ── ゲームのUI     : 4種類の行動 + HUD + 報酬
Tiimo        ── 認知のUI       : 時間の箱 + 絵文字 + 穏やかな完了
Structured   ── 時間のUI       : 1本の縦線 + 空き時間 + 日付
```

これらは排他ではない。**自分のプロダクトがどの問いに答えるのか**を決め、
必要なパラダイムだけを混ぜるのが正しい。全部を混ぜると、5つの弱点がすべて出る。

## 7. アンチパターン（5アプリの失敗から）

| アンチパターン | 出典 | なぜダメか |
|---|---|---|
| 1つのチェックボックスで全部を扱う | Habiticaの反例 | 習慣・単発・報酬では完了の意味が違う |
| 空き時間を空白のままにする | Toggl/Structuredの反例 | ユーザーは「何をすべきか」を探している |
| 色をプロジェクト数だけ増やす | Toggl | 20色を超えると識別不能 |
| 巨大な動画ヒーロー | Structured | LCP悪化、モバイルで重い |
| 常駐AIチャット | Asana | コンテンツを覆う |
| ゲーミフィケーションの多用 | Habitica | 業務ツールでは幼稚に見える |
| 低コントラストのパステル本文 | Tiimo | 可読性が落ちる |
| 5層の階層を個人に強いる | Asana | 個人のTodoには過剰 |
