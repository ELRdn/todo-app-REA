# 02. Toggl — 時間を「台帳」にするUI

> 観察対象: `toggl.com`（マーケティング）, `accounts.toggl.com/track/login`（ログイン）, 公式プロダクト画像5点
> Evidence: `ev_3ba26693…`, `ev_d5acfddc…`, `ev_989e7576…`

---

## 1. プロダクトの位置づけ

Togglは「ToDoを終わらせる」アプリではなく、**使った時間を記録し、金額・稼働・利益に変換する**プロダクト。
UIの中心はタスクではなく **タイムエントリ**。1つのエントリは「何を・誰が・いつ・何時間」を持ち、
それがプロジェクト→クライアント→請求へと集計される。

`[OBS]` 2026年のトップコピーは "The time tracker millions trust"。
サブコピーは "Toggl gives teams the time data they need for better **capacity, profitability, and project planning**."
`[INF]` つまり「記録」ではなく「経営判断の材料」。UIもレポート寄りに振れている。

- **浮遊するピル型ナビ**。画面端から16px離れ、角丸は実測 **445px**（=完全なピル）。影は非常に薄い。
  `[INF]` 白い帯を画面に固定せず「浮かせる」ことで、背景のクリーム色とタイムラインの連続性を保っている。
- **背景はクリーム `#F8F7F1`**。白ではなく、紙のような暖色。長時間見ても刺さらない。
- **ヒーロー直下に商品の実物**（Weekly report / Team activity）。抽象的なイラストではなく、**数字と表**。
- **左右に時計の目盛りのような装飾**（ピンクの目盛り）。時間がテーマであることを、文字以外で示す。

- **左の細いダークレール（72px）**。最上部にピンクの円形ロゴ（=電源ボタンのような形）。ここだけがブランド色。
- **フィルタはすべてピル**。`Profitability ▾` `This week • W33` `EUR ▾`。高さ44px、角丸10–12px、1pxボーダー。
- **KPIカード**は数字が主役。ラベルは12pxグレー、数値は28px。単位は小さく同じ行に置く。
- **グラフ**: 積み上げ棒（Revenue / Revenue forecast / Cost / Cost forecast）+ 破線の利益ライン。
  予測を「別の系列」として重ねることで、実績と見込みを同じ軸で読ませる。
- **テーブル**: プロジェクト名の前に**色のドット**。色がプロジェクトIDになっている。
  右端のマージンは緑（48.1%）/赤（23.1%）のバッジ。**数字の良し悪しを色で即断**できる。
- **フォントはInter**。マーケティングのAeonikとは別。プロダクトはニュートラルなサンセリフ。

### 2.4 キャパシティ画面（`evidence/toggl/product/capacity-planning.png`）

- 行 = 人。左にアバター、名前、役割、`0h free` / `1h 20m free` の**空き時間バー**。
- 列 = 週。上部に `Week 33`、`3h over capacity` のツールチップ。
- ブロック = プロジェクト。色はプロジェクト、右端に `8h / day`。
- 空き時間が**マイナスになると赤いバー**。`[INF]` 「空き」をポジティブな資産として扱っている。

### 2.5 ログイン（`evidence/toggl/screenshots-login/login.png`）

- 背景はほぼ黒 `#1C1A1C`、中央に幅360pxのカード。
- ロゴはピンクの手書き風 `toggl track`。
- 入力は36px、角丸8px、1px `#575456`。CTAはピンク `#CD7FC2` に黒文字。
- ソーシャルログインはダーク背景 + 1pxボーダー。`Google / Apple / Passkey / SSO` の4つ。
- `[INF]` マーケティングのクリームとは正反対のダーク。ログインは「プロダクトの世界」への入口として色を反転させている。

| H2 | 60.52px / 600 | |

**特徴**: 14.24 / 17.8 / 21.36 / 40.94 / 60.52 / 74.76 という**0.89倍でスケールする非整数値**。
`[INF]` ルートフォントサイズを可変にして、画面幅に応じて全てを比例拡大する設計（Webflowのrem運用）。
結果として、どの幅でも「同じ比率のタイポグラフィ」になる。

**組み合わせ**: クリーム + 濃紫 + ライム + ピンク。**4色だが、面積はクリーム80% / 紫15% / ライム4% / ピンク1%**。

### 3.3 角丸・影

- radius: **445px**（ナビピル）、14.24px（カード）、10.68px（ボタン）、7.12px（小要素）、50%（アバター）
- shadow: `0 0 24px rgba(0,0,0,.06)`、`0 1.78px 28.48px rgba(236,132,255,.08)`
- フォーカスリング: `0 0 0 4px #FAE0FE`（ピンクの輪）

**特徴**: 影はほぼ見えない。**境界は影ではなく、面の色差と1pxボーダーで作る**。

## 5. インタラクション

| 操作 | 挙動 | 根拠 |
|---|---|---|
| タイマー開始 | 再生ボタン → 数字が進む、エントリが増える | `[PROD]` ヒーロー |
| フィルタ変更 | レポート全体が再集計 | `[OBS]` UI |
| プロジェクト色 | 色ドット・ブロック・凡例で同一色 | `[PROD]` |
| キャパシティ超過 | 赤いバー + ツールチップ `3h over capacity` | `[PROD]` |
| スクロール | タイムラインのブロックが積み上がる | `[INF]` |
| ホバー | ピンクの4pxフォーカスリング | `[OBS]` CSS |

モーションは「時間が進む」感覚を優先。`[INF]` 数字のカウントアップ、バーの伸長、ブロックの積み上げ。

## 6. このUIの強み

1. **数字が主役**。ラベルを小さく、数値を大きく。単位を同じ行に置く。比較が一瞬でできる。
2. **時間軸が画面の骨格**。マーケティングでもプロダクトでも、縦線とブロックが同じ文法で使われる。
3. **色 = プロジェクト**。凡例・ドット・ブロック・テーブルが同じ色を共有。色がIDになる。
4. **空き時間を可視化**。`0h free` / `3h over capacity`。余白を「情報」に変えている。
5. **マーケティングとプロダクトでトーンを分ける**。クリームの世界 → ダークのログイン → 白のプロダクト。

## 7. 弱点・真似しない方がいい点

- **情報密度が高い**。14px本文 + 多数のフィルタ。個人のTodoには過剰。
- **「時間を測る」前提**。タイマーを押し忘れるとデータが壊れる。手入力の導線が弱い（推論）。
- **色がプロジェクト数だけ増える**。プロジェクトが20個を超えると識別が破綻する。
- **マーケティングの非整数スケール**は実装が特殊。デザインシステムとしては再現しづらい。

## 8. 盗むべきもの

| 原則 | 移植方法 |
|---|---|
| 数字を主役に | 今日の完了数・集中時間・残り時間を大きく1つだけ表示 |
| 空き時間をオブジェクト化 | 「次の空きは 14:30–15:15（45分）」をカードで提案 |
| 色 = プロジェクト | タグ色をプロジェクト色と一致させ、リスト・タイムライン・集計で共有 |
| ピル型フィルタ | 期間・カテゴリ・優先度をピルで横並び |
| 予測を実績に重ねる | 今日の残りを「予測」として薄く表示 |
| 影ではなく面で境界 | カードの境界は1px + 背景色差。影は最小 |
